## 3rd Eye Supply — Production Playbook (Astro + GitHub Pages + Snipcart + Cloudflare + CJ)

This document is the single source of truth for how this website is built, deployed, extended, and debugged. It prioritizes official methods and stability. Keep this file up to date and treat every change as part of the release process.

### Canonical URL and Hosting Model
- Canonical site URL: `https://hopehamster.github.io/3rd-eye-supply/`
- Hosting: GitHub Pages (Project Pages) deployed via GitHub Actions (official `upload-pages-artifact` + `deploy-pages`).
- Source branch: `main` builds the site artifact; Pages environment deploys it.

### Repository Layout (current)
- `site/` — Astro project root
  - `astro.config.mjs` — MUST include `base: '/3rd-eye-supply'` and `site: 'https://hopehamster.github.io'`
  - `public/` — Current static pages and assets (acts as source content for now)
  - `dist/` — Build output (generated by CI; never commit)
- `.github/workflows/gh-pages.yml` — Official Pages workflow
- `.nojekyll` — Required to prevent Jekyll from stripping `_astro/` assets
- `images/` — Legacy assets mirrored under `site/public/images/` (the build pulls from `site/public`)

If both root-level HTML and `site/public` versions exist, the build artifact created by Astro (from `site/`) is the source of truth. Root HTML duplicates should be retired once the site is verified.

## Build and Deploy (Official)

### Astro configuration
```js
// site/astro.config.mjs
import { defineConfig } from 'astro/config';
import tailwind from '@astrojs/tailwind';
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://hopehamster.github.io',
  base: '/3rd-eye-supply',
  integrations: [tailwind(), sitemap()],
});
```

Key rules:
- Always set `base: '/3rd-eye-supply'` for Project Pages. This ensures all generated links start with the project base.
- Do not use absolute root paths `/...` that ignore the project base. Use project-absolute `/3rd-eye-supply/...` or let Astro generate them.

### GitHub Actions (Pages)
Workflow file (already present): `.github/workflows/gh-pages.yml`

Important details:
- Uses `actions/upload-pages-artifact@v3` to package `site/dist`.
- Uses `actions/deploy-pages@v4` to deploy the artifact to the Pages environment.
- Pages Settings → Source: GitHub Actions.

### Deploy steps (local)
1) Commit changes to `main`.
2) GitHub Actions runs the build and deploy automatically.
3) Wait for green check and “Deployed to github-pages”.
4) Verify at `https://hopehamster.github.io/3rd-eye-supply/` with a hard refresh.

## Pathing Rules (Critical for GitHub Pages)

1) Project base: all links must resolve under `/3rd-eye-supply/`.
   - CSS/JS: `<link rel="stylesheet" href="/3rd-eye-supply/_astro/...">`
   - Images: `<img src="/3rd-eye-supply/images/...">`
   - Nav links: `/3rd-eye-supply/shop`, `/3rd-eye-supply/category/...`, etc.
2) Case-sensitivity: filenames and references must match exactly (GitHub Pages is case-sensitive).
3) `_astro/` directory: keep `.nojekyll` at repo root to avoid Jekyll stripping underscore-prefixed files.
4) Avoid submodules and nested `.git` folders in the repo (Pages can choke on them).
5) Prefer hashed assets (Astro does this) and append `?v=` query for manual cache-busting if needed.

Common anti-patterns to avoid:
- Using plain `/images/...` or `/_astro/...` (that points to the host root, not the project base).
- Mixing relative paths across nested directories; prefer project-absolute with the base.

## Snipcart Integration (v3)

### Client-side include (already present)
```html
<div id="snipcart" hidden data-api-key="[PUBLIC_KEY]"></div>
<script defer src="https://cdn.snipcart.com/themes/v3.4.1/default/snipcart.js"></script>
<link rel="stylesheet" href="https://cdn.snipcart.com/themes/v3.4.1/default/snipcart.css">
```

### Product buttons (examples)
- Simple add-to-cart button:
```html
<button
  class="snipcart-add-item"
  data-item-id="sku-123"
  data-item-name="Product Name"
  data-item-price="29.00"
  data-item-url="/3rd-eye-supply/products/product-slug"
  data-item-description="Short description"
>
  Add to Cart
</button>
```

### Webhooks (server-side)
- Snipcart sends a request containing a request token. Validate it server-side using the Snipcart Secret API Key.
- Pattern: read token header, call Snipcart API with Secret API Key to fetch event details, then process.
- Keep your Secret API Key in server-side secrets only (e.g., Cloudflare Worker secrets).

## Cloudflare Workers + KV (Automation)

We use Workers for:
- Processing Snipcart webhooks
- Polling CJ for tracking updates
- Syncing CJ inventory and prices hourly

### High-level setup
1) Create KV namespaces (Dashboard → Workers & Pages → KV):
   - `orders_state` (webhook state)
   - `products` (inventory and SKU mapping)
2) Bind KV to the Worker (Settings → Variables and Bindings → KV Namespace bindings):
   - `ORDERS_STATE` → `orders_state`
   - `PRODUCTS` → `products`
3) Add secrets (Settings → Variables):
   - `SNIPCART_SECRET_API_KEY`
   - `CJ_API_KEY`
4) Deploy Workers (via Dashboard or Wrangler). Ensure routes for any public endpoints if needed.

### Minimal Worker verification flow (Snipcart webhook)
1) Receive POST with token header.
2) Validate by fetching the request details using Secret API Key.
3) Write order status to `ORDERS_STATE`.
4) Optionally enrich inventory in `PRODUCTS`.

## CJdropshipping API (Initial Integration)

Purpose:
- Import new products periodically, keep inventory/price in sync, and fetch tracking updates.

Basics:
- Authentication: use CJ API key (keep as secret in Worker).
- Typical flows:
  - Product search/importer: query CJ catalog → select items → write to `PRODUCTS` and generate product pages/cards.
  - Inventory/price sync: hourly job reads `PRODUCTS`, calls CJ API for latest stock/price, updates KV, and (optionally) patches displayed prices.
  - Tracking updates: scheduled job queries CJ for shipped orders and posts updates (email/Slack/etc.).

## Verification Checklist (Every Deploy)

- Pages Settings → Source: GitHub Actions (confirmed)
- CI green for build and deploy
- Open with cache disabled:
  - `/3rd-eye-supply/` (homepage): hero images load
  - `/3rd-eye-supply/shop/`: all cards show images
  - A category page loads images
  - A product page loads images
- Network tab:
  - CSS: 200 for `/3rd-eye-supply/_astro/...css`
  - Several images: 200 for `/3rd-eye-supply/images/...`
- Snipcart modal appears and can add an item

If any asset 404s:
1) Confirm path in HTML begins with `/3rd-eye-supply/`.
2) Confirm filename and case match in `site/public/images/...`.
3) Rebuild via CI; hard refresh or add `?v=` query to bypass cache.

## Triaging “Looks unstyled / blank images”

1) Confirm the URL includes `/3rd-eye-supply/`.
2) View Source → check `<link rel="stylesheet" href="/3rd-eye-supply/_astro/...css">`.
3) Open the CSS directly; expect 200.
4) Open one image directly; expect 200.
5) Fix any incorrect paths in `site/public/*.html` and re-deploy.
